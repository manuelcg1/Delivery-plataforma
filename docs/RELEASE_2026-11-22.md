# Release 2026-11-22: entrega segura, reasignación y chat

Rama: `codex/entrega-segura-reasignacion` · App `0.8.0+9` · Migraciones `V38`, `V39`.
Procedimiento general: [PRODUCTION.md](PRODUCTION.md).

## 0. Antes de empezar (bloqueos)

- [ ] **Documentos legales completos.** Reemplazar todos los datos entre corchetes en
      `backend/src/main/resources/legal/*.md` (razón social, RUC, domicilio, correos,
      plazos, banco de datos ANPD) y, de preferencia, revisión de un abogado. Los usuarios
      los ven al registrarse.
- [ ] **Compatibilidad con APK antiguos.** Este backend exige el código de entrega para
      marcar "Entregado" y la aceptación legal para registrarse. Un repartidor con el APK
      anterior no podrá finalizar entregas. Publicar el APK `0.8.0+9` **en la misma
      ventana** que el backend y pedir a clientes y repartidores que actualicen.
- [ ] **Clave de firma Android de producción** disponible (ver sección 2). Si se pierde,
      la app no se puede actualizar sobre las instalaciones existentes.
- [ ] Ventana de mantenimiento acordada: sin pedidos en curso o avisados.

## 2. APK de producción (en tu PC, Windows)

Solo la primera vez, si aún no existe la clave de subida (guárdala fuera del repo y
con respaldo; `keytool` pedirá las contraseñas):

```powershell
New-Item -ItemType Directory -Force C:\secure
```

```powershell
keytool -genkeypair -v -keystore C:\secure\delivery-customer-upload.jks -alias delivery-customer-upload -keyalg RSA -keysize 2048 -validity 10000
```

```powershell
Copy-Item customer-app\android\key.properties.example customer-app\android\key.properties
```

Editar `customer-app\android\key.properties` con la ruta, alias y contraseñas reales
(el archivo está en `.gitignore`).

Compilar (usa Java 21 de Android Studio y apunta a `https://api.cerka.site`):

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
```

```powershell
cd customer-app; .\scripts\build-release.ps1 -Environment production -ApiBaseUrl https://api.cerka.site -WsBaseUrl wss://api.cerka.site
```

Verificar firma y versión antes de distribuir:

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\build-tools\35.0.0\apksigner.bat" verify --print-certs build\app\outputs\flutter-apk\app-release.apk
```

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\build-tools\35.0.0\aapt.exe" dump badging build\app\outputs\flutter-apk\app-release.apk | Select-String "versionCode"
```

Debe mostrar `versionCode='9' versionName='0.8.0'` y el certificado de tu clave (no
`CI Audit` ni `Verificacion local`). Ajusta `35.0.0` a la carpeta de build-tools que
tengas instalada.

## 3. Servidor de producción (Linux)

```bash
cd /ruta/a/Delivery-plataforma
```

Respaldo de base de datos:

```bash
mkdir -p backups && docker compose --env-file .env.production -f docker-compose.prod.yml exec -T postgres pg_dump -U delivery -d delivery -Fc > backups/delivery-$(date +%Y%m%d-%H%M%S).dump
```

Respaldo de MinIO (fotos, QR Yape, pruebas de entrega):

```bash
docker run --rm -v "$(docker volume ls -q | grep minio_prod_data)":/data:ro -v "$PWD/backups":/backup alpine tar czf /backup/minio-$(date +%Y%m%d-%H%M%S).tgz -C /data .
```

Comprobar que los respaldos no están vacíos y copiarlos fuera del servidor:

```bash
ls -lh backups/
```

Actualizar al tag y validar la configuración:

```bash
git fetch --tags && git checkout v0.8.0
```

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml config --quiet
```

Construir y levantar:

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml build
```

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml up -d
```

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml ps
```

Confirmar las migraciones y el arranque:

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml logs backend | grep -E "Migrating schema|Successfully applied|Started DeliveryPlatformApplication|ERROR"
```

Debe aparecer `version "38 - secure delivery code"`, `version "39 - legal acceptances"`
y `now at version v39`.

Pedido completo (un cliente, un repartidor y el portal)
- [ ] Al crear el pedido aparece "¡Pedido creado!" con el código de 5 caracteres y el mensaje de seguridad; el número es corto (`CK-XXXXXX`).
- [ ] El QR Yape carga y la declaración queda pendiente de revisión del comercio.
- [ ] El detalle del cliente muestra el código, "Ver productos" y el seguimiento con íconos.
- [ ] Asignar repartidor con la app en segundo plano: la notificación muestra **ACEPTAR/RECHAZAR**.
- [ ] RECHAZAR: el portal muestra "Rechazado por el repartidor" y permite asignar otro al instante.
- [ ] ACEPTAR: el portal muestra "Aceptado por el repartidor" y el mensaje "Entrega aceptada…".
- [ ] "Cancelar asignación" y "Reasignar" funcionan antes del recojo y no después.
- [ ] El repartidor ve "Ver productos" (sin precios) y el punto de recojo; "Ir al destino del cliente" y "Chatear" aparecen solo desde "En camino".
- [ ] Chat en ambos sentidos: llega push, el número rojo aparece en "Chatear" y desaparece al abrir; el chat muestra "Nuevo".
- [ ] Al llegar: un código incorrecto indica intentos restantes; el correcto habilita "PEDIDO ENTREGADO".
- [ ] El cliente ve todos los pasos completados y puede calificar.
- [ ] Búsqueda dentro de un comercio: filtra al escribir, sin cerrar el teclado.

Pedidos que estaban en curso al desplegar
- [ ] Tienen código generado por la migración: el cliente lo ve en el detalle con el APK nuevo.

## 5. Rollback

Las migraciones V38 y V39 solo agregan tablas y no cambian columnas existentes. Para
volver atrás:

```bash
git checkout <tag-anterior>
```

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build
```

El backend anterior ignora las tablas nuevas. Si hubiera daño de datos, restaurar el
respaldo en un entorno aislado antes de tocar producción (ver [PRODUCTION.md](PRODUCTION.md)).
